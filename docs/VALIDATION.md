# 0.4.0 验证记录

2026-11-14，Windows、ZCode Desktop 3.18.2 与本机 Codex Desktop。

## 已完成的实机检查

- 通过标准 MCP stdio 创建独立工作区会话，选择已配置的模型，继承当前调用方的完全访问权限。
- 派发真实模型任务，先持久化订阅，再发送输入；观察原生 `turn.started` 中的输入 ID 和消息 ID，关联到对应轮次。
- 两次任务分别执行 20 秒和 90 秒等待命令并返回指定标记。两次均产生一个 `turn.completed`，宿主投递均只尝试一次并成功。
- 第二次派发后，来源 Codex 会话结束本轮；ZCode 完成后，插件通过第一方标准 MCP `send_message_to_thread` 将同一会话接回，代理实际继续验收。无需用户追加消息。
- 核对终态时没有活动工具、后台工作或待处理问题；随后确认事件，未重排已投递的通知。
- 当前请求的来源信息支持对象和 JSON 字符串形式；不把子代理正文复制进唤醒消息。

## 回归与打包检查

- 248 项自动化测试：覆盖终态证据、初次发送、来源绑定、权限继承、幂等、取消、确认、重启状态和宿主适配器。
- 实际 3.18 消息及事件形状的离线回放，验证轮次关联；真实 Bridge 到 Client 的接线检查。
- 两侧插件从同一份 `runtime/` 生成，并检查生成一致性。
- 源码与归档检查：不包含作者本机工作区、模型私有编号、凭据、会话、数据库或运行日志。

## 版本与证据边界

第一方宿主接口会随客户端版本变化。插件在运行时探测能力；缺少接口或投递失败时，持久事件仍可通过收件箱读取。单次 `delivered` 只表示宿主接受消息，本记录额外验证了来源会话实际继续工作。

独立引擎不会向已打开的 ZCode Desktop 页面持续推送会话与消息。`desktop.indexed` 只说明索引收录，不能证明页面显示。0.4.0 不包含实验性 Desktop 补丁，也不声称修复实时页面刷新。

早期完整集成基线为 Desktop 3.17.2 / engine 0.17.1；0.3.1 增加了 3.18.2 消息标识与分页兼容。未对其他系统或未来客户端版本作同等实机保证。原始验收会话、日志及宿主连接信息仅保存在测试机器，不随仓库发布。
